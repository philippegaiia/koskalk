### Key load-bearing fact for future reviews
The renderer still **hard-fails** on draft shape / claim shape / 160-word cap
(`IngredientGuidanceDraftRenderer::invalid()`). That is only safe because
`OpenAiStructuredOutputTransport` sends `strict: true` (:51) — OpenAI then guarantees the schema,
so the exact-key checks in `validateDraftShape`/`validateClaim` cannot be tripped by a compliant
model. **If anyone ever drops `strict` or adds an optional claim field, fail-fast returns** and a
10-minute run dies on one malformed claim. This is the invariant to protect.

### Findings raised (plan delivered, not yet fixed)
1. **MAJOR — retry budget exceeds job timeout.** `openai.timeout_seconds` = 600 (config:99),
   transport retries twice more on 5xx/429/ConnectionException (transport:37-41) → worst case
   ~1800s, but both jobs set `$this->timeout` = 900 (config:66; Job:27-28). A retried slow call
   can therefore be SIGKILLed mid-flight, producing the "killed worker orphan" state the handoff
   treats as environmental (items 44/48/49). Derived from config arithmetic, **not** observed live.
2. **MINOR — empty sections render after mass drops.** DraftRenderer:53 emits `## Heading` with no
   body if every claim in a section is dropped. `soapmaking` guards `$claims === []` (:33) but not
   "all dropped". Drop-and-warn makes this far more likely than before.
3. **MINOR — code-leak guard is substring, not word-bounded** (:217, `str_contains`). Short tokens
   can false-positive and silently drop a good claim; also only covers `evidence`-supported
   claims, not `fact`-supported ones.

i.e. `.agents/skills` is deliberately **not scanned** by the runtime and not listed in settings;
support is a deferred open follow-up. This is an upstream limitation, not local misconfiguration.

Bridge: copied the 9 skills into `.workbuddy-ai/skills/` (project level) — WorkBuddy *does* read
that. `scripts/sync-boost-skills.sh` re-syncs; run it after `php artisan boost:update`, which
rewrites `.agents/skills` and would otherwise leave the mirror stale.

- Copies, **not symlinks**. Could not verify the scanner traverses directory symlinks, and a real
  dir is unambiguous for any `readdir(..., {withFileTypes:true})` + `isDirectory()` filter. The
  `isSymbolicLink` hits in `app.asar` are chokidar's, not the skill scanner's — inconclusive.

  (`.agents` = 896K w/ `scripts/`+`agents/`; `~/.workbuddy-ai/skills` = 264K w/ `references/` +

- Skill registry is **built at session start and cached**. Adding a skill mid-session does not
  make it callable — a real (non-symlink) copy still failed `Skill` lookup. Don't re-test in the
  same session; it needs a fresh one to take effect.
