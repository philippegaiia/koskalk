## Addendum — reconciliation with a second independent review (verdict CHANGED)

A second reviewer (Claude Opus 4.6) reviewed the same tree. Two findings matched mine
independently (subdomain self-corroboration — I upgraded mine P2→**P1**; punctuation defeats the
qualifier strip — held at P2). It also added two I verified and adopted:

- **[P1] Two-authority audit trail is LOST ON APPLY** (pre-existing, not from fixes 1–9).
  Verified empirically via reflection: evidence rows for one corroborated identifier go 2 → 1 on
  edit. `value_provenance` (which keeps both URLs) survives **on the item** but is **never** passed
  to `IngredientDataEntryService::syncCurrentData` — `ApplyPlatformIngredientEnrichment:245` builds
  only `identifier_evidence`, one entry per identifier from that identifier's own single
  `source_url`. So the applied ingredient carries an `approved_secondary`/`supported` CAS/EC naming
  ONE supplier while the rule that admitted it required two. Breaks the `.ai/rules:14` invariant
  that provenance stays stored and independent.
- **[P2] FDA discovery can terminate on a non-authoritative alias.** Verified: a derivative with
  `names[]` = base name satisfies `batchNamesTermExactly` (it checks `names` too) → discovery
  stops; but `scoreCandidate()` only considers `inci_name`+`inci_names` → matcher rejects it →
  gate. Different mechanism from the tie-gating I found; both live. Restrict the stop predicate to
  the matcher's name set.

**Revised verdict: do not ship the corroborated-CAS/EC path to production** until finding A is
fixed. The nine fixes themselves are sound; the blockers are now about the evidence trail around
them.
