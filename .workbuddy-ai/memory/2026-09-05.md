## Correction: the `Viewer` role does not exist — F1's actor was wrong

Owner pushed back on §4.9 ("no real viewer... you need to be connected to access this app part").
They were right, and investigating it changed a finding.

**Evidence that `WorkspaceMemberRole::Viewer` is vestigial** (`app/Enums/WorkspaceMemberRole.php:10`):
- Declared, then referenced **nowhere** — not `app/`, `resources/`, `routes/`, `database/`, `tests/`.
  Only hits for "viewer" elsewhere are unrelated (`ReviewerSupplied`, `reviewer_edited` enums).
- No member-management UI at all: no Filament resource, no Livewire component, no invite route. The
  only membership insert in app code is workspace creation → `Owner` (`SettingsIndex.php:167`).
- `WorkspaceMemberFactory` defaults to `Editor`; DB query `SELECT role, COUNT(*) FROM
  workspace_members GROUP BY role` → **2 rows, both `owner`**.
- Every capability check names only Owner/Admin/Editor.

**So F1's actor is a non-member, not a Viewer.** The reachable path: a **public, workspace-owned**
ingredient opened by an authenticated user who is not a member of that workspace. Route admits them
because `IngredientController::edit()` (`:38-41`) passes on `isAccessibleBy()`, and
`Ingredient::isAccessibleBy()` (`:387`) is satisfied by `isPublicCatalog()` alone — i.e.
`visibility === Public` (`:352`) — no membership condition. Then `workspaceRoleFor()` → null →
`isEditableBy()` false → `isReadOnly()` true → Save bar rendered (`isPlatformIngredient` false) →
403 at `:210`. Local DB has **0** public workspace-owned ingredients (3 private, 168 platform), but
`visibility` is user-settable so the path is live.

F1's **validity survives; its likelihood and its actor change.** The §4.1 fix (gate `:185` on
capability not origin) is unchanged and is now justified for the role set that exists today, with
Viewer covered for free if it is ever wired up.
