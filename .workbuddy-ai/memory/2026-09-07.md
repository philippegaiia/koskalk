### WCAG 2.5.3 on the two clickable summary tiles

Both count tiles had `aria-label="Negative forecast"` / `"Below buffer"` while their **visible text is
the number** — a screen reader announced the state and never the count, and voice-control users
could not say what they see. Fixed to `<term> (<count>)`, e.g. `aria-label="Below buffer (1)"`.
Also chose the `<dt>`'s term (`production.shortage`) over the filter panel's wording
(`filter_negative_forecast`) so the name matches the label directly above the control — the two
names for one state is itself a finding, reported not fixed. Both keys already existed, so no
catalogue churn. Test: `it('names the clickable summary tiles with their visible count')`.

### The `--color-ink-muted` AA failure — fixed systemically

`resources/css/shared/soapkraft.css:49`, `oklch(58.0% 0.012 75)` → `oklch(52.0% 0.012 75)`. The
token's own comment called it "the one line to darken if the 10px help text proves too faint", so
this was the sanctioned knob, and it is the only definition (no dark-mode override, no test asserts
the value).

Measured (linear sRGB luminance, script asserted against a hand calculation of 4.107:1):

| background | at 58% | at 52% |
| --- | --- | --- |
| `--color-panel` 98.5 | 4.11 FAIL | 5.28 |
| `--color-panel-muted` 96.4 | 3.86 FAIL | 4.97 |
| `--color-surface` 96.4 | 3.88 FAIL | 4.99 |
| `--color-panel-strong` 93.4 | 3.53 FAIL | 4.54 |
| own `/10` pill tint | 3.65 FAIL | 4.60 |
| `--color-field` 99.4 | 4.22 FAIL | 5.42 |

52% is the **lightest** value clearing 4.5:1 everywhere including the self-referential pill — that
one is the binding constraint, because `bg-[var(--color-ink-muted)]/10 text-[var(--color-ink-muted)]`
darkens its own background as the token darkens, so it gains the least. `ink-soft` is 46.5%, so the
hierarchy step survives.

**Contrast-script traps, hit twice in one session:** (1) tokens are written in **percent** — feed L
as 0.985, not 98.5; getting this wrong gave a plausible-looking 4.90:1 instead of 4.11:1. (2) don't
round-trip an oklab mix back through `oklch_to_oklab` (it divides L by 100 again). Always assert one
hand-computed pair before trusting the table.

### Two systemic checks (both came back "not what I assumed")

- **The dropdown-behind-sticky-thead collision is unique to `inventory-index`.** Only three sticky
  theads exist: `batch-size-form.blade.php:58` and `task-set-form.blade.php:87` are both `z-10` with

  "page title = first card title" is the established convention across at least three production
  bench screens. Fixing it here alone would make this screen the odd one out — it is a cross-screen
  decision, and I should not have filed it as a defect in this screen.
