## The one HIGH: `--color-ink-muted` fails contrast

Measured (oklch → linear sRGB → WCAG, script in /tmp/contrast.py — recompute, don't trust the numbers
blind):

| pair | ratio | needs |
|---|---|---|
| `ink-muted` on `panel` | **4.11:1** | 4.5:1 (12px) — FAIL |

pipeline is right.

`ink-muted` is used in ~15 more places across production-bench, several on `surface-muted` which I
did **not** measure. Reported as one systemic token finding. Left the colour alone per
`better-colors` ("leave the colors alone unless asked"); proposed the local fix = swap that one

## Sticky thead (follow-up, same turn)

Owner asked for a sticky `<thead>` too. **The non-obvious part is not `sticky top-0` — it is the
scroll container.** `overflow-x: auto` computes `overflow-y` to `auto` as well, but with no height
the wrapper never scrolls, so `sticky top-0` on the thead does nothing. Fix is to bound the
wrapper: `max-h-[70dvh] overflow-auto`. Confirmed by the project's own precedent at
`production/batch-size-form.blade.php:56` (`max-h-[28rem] overflow-y-auto` + `sticky top-0 z-10`).

Used `dvh` not `vh` — the codebase already uses `max-h-[88dvh]` / `max-h-[56dvh]`
(`media-asset-picker.blade.php`). `dvh` handles mobile browser chrome.

**z-index layering matters** and is easy to get wrong: thead `z-20`, corner `<th>` `z-30`, sticky
body `<td>` `z-10`. thead must outrank the sticky body cell or the column covers the header while
scrolling down; the corner th must outrank its sibling ths while scrolling right.

Added a guard test (`keeps the material header visible while the rows scroll`) because deleting the
max-height unsticks the header while all data assertions still pass. 44 tests pass, Pint clean.

## Page scroll instead of a capped table (commit `d5676b6f`)

Owner: "if we keep a max height then there is no point in have a 'rows per page' selector". Correct,
and it applied to both tabs. Height cap removed from both; the page scrolls and the thead sticks to
the viewport. Implementation is a **container query**, not a media query: the card gets
`@container overflow-clip`, the wrapper `overflow-x-auto @min-[70rem]:overflow-x-visible`
(materials, floor 1120px) / `@min-[65rem]` (lots, floor 1040px). Below the threshold you keep
horizontal scroll and lose the sticky header — verified in headless Chrome, not assumed.

Also in that commit: the lot status pill became a dot, freeing the width that was pushing the
stocked-on date onto a second line (date is now `whitespace-nowrap`).

### Dot colour: the owner was right, `-strong` is wrong for dots

I first used `success-strong` / `warning-strong` — `#00422e` (11.2:1) and `#8a3f04` (7.2:1). At
8–10px both read as "a dark dot". Switched to the **base** tones `#257055` (5.78:1) and `#b45307`
(4.86:1): 120° apart in hue, both mid-lightness, both clear 3:1 non-text.

Rule worth keeping: `-strong` tokens exist for *text on soft backgrounds*, where you want maximum
contrast. For a small filled shape that has to be told apart from another small filled shape, use the
base tone — hue separation and mid lightness beat raw contrast. The below-buffer dot on the
materials tab still uses `warning-strong`; that dot has no sibling state to be distinguished from,
so darkness costs it nothing. Left alone deliberately.

tags (`@if … <a …>` / `@else <div>` … `@endif` … `@if … </a>` / `@else </div>` / `@endif`). Ugly,
but it keeps one copy of the inner markup; use `<span class="block">` children so the same lines
work in both branches.
