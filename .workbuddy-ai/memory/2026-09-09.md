## Gotchas hit (now in reference/css-and-ui.md)

- Dev-server CSS is **unminified** — compact `grep -o` patterns silently match nothing, and
  BSD `grep` has no `\s`. I briefly concluded `max-w-app` "wasn't compiling" on that basis.
- Tailwind's dev cache **keeps** rules for deleted classes, so the bundle showing both
  `.max-w-[1180px]` and `.max-w-app` is expected, not a failed swap.
- `npm run build` is blocked in this sandbox (Vite `loadEnv` reads `.env`). Use `?direct`.
- `Illuminate\Testing\TestView` has **no `toHtml()`**. Use `view('welcome')->render()`.

## Inventory: closed the last open accessibility gap

The independent reviewer had left "browser accessibility remains unverified" open. One real
failure mode was still unchecked: **a dangling `aria-describedby`.** The test proved the
attribute sits on the `<input>` but not that the id it names exists in that mode's markup —
a reference pointing at the other tab's help paragraph would resolve to nothing and still
read green.

Both ids do exist and each renders in its own mode. Strengthened
`ProductionBenchPagesTest` → "points the inventory search inputs at their help text" with
`expect($html)->toContain('id="'.$case['helpId'].'"')`. Confirmed the assertion can fail:
the two help paragraphs sit in mutually exclusive branches (`@if ($mode === 'materials')`
at `inventory-index.blade.php:17`, register in the else), so it discriminates rather than
passing trivially. Committed `ac96e4c6`.

Lesson recorded in `reference/reviewing.md`: an attribute assertion is not a target
assertion — assert both, then prove the new assertion can fail.
