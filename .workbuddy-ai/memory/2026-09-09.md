## Gotchas hit (now in reference/css-and-ui.md)

- Dev-server CSS is **unminified** — compact `grep -o` patterns silently match nothing, and
  BSD `grep` has no `\s`. I briefly concluded `max-w-app` "wasn't compiling" on that basis.
- Tailwind's dev cache **keeps** rules for deleted classes, so the bundle showing both
  `.max-w-[1180px]` and `.max-w-app` is expected, not a failed swap.
- `npm run build` is blocked in this sandbox (Vite `loadEnv` reads `.env`). Use `?direct`.
- `Illuminate\Testing\TestView` has **no `toHtml()`**. Use `view('welcome')->render()`.

assertion — assert both, then prove the new assertion can fail.

## Broke the production build with a memory note — my error, owner fixed it

I wrote a class-shaped placeholder with a symbolic measurement into tracked Markdown
(`.workbuddy-ai/memory/2026-09-08.md`). `app.css` uses a bare `@import 'tailwindcss'`, so
Tailwind auto-scans every non-gitignored file **as plain text** — backticks and code fences
mean nothing to it. It read the placeholder as a real utility, emitted a container query with
an invalid measurement, and the production minifier rejected it. The suite stayed green the
whole time, because contract tests only ever read Blade source, never generated CSS.

Owner fixed it in `67caa8d1` by rewriting the sentence as prose. Verified afterwards: no other
instance of a symbolic placeholder in any tracked Markdown, and the only trace left in the dev
bundle is Tailwind's dev cache retaining the removed class — a fresh build will not emit it.

Two things I had written that were wrong:
- **"`npm run build` is blocked" was false as a general claim.** It is blocked for *me*, by my
  sandbox. The owner runs it fine, and it has to be run after UI or CSS work.
- **The build is the only thing that catches malformed generated CSS.** PHP tests cannot. So
  "suite green" never implied "assets build".

Recorded in `reference/css-and-ui.md` and `reference/testing-and-git.md`, written in prose
precisely so the note cannot reproduce the bug it describes.
