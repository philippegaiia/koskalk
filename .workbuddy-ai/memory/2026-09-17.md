# 2026-09-17

## Reviewed proposal to redesign the productions list (production bench → productions)

Analysis only, no code changed. Reviewed the proposed two-line compact table against
`ProductionIndex.php` + `production-index.blade.php`. Agreed in substance; raised 4 amendments.

Findings worth keeping (all in the current index, not the proposal):

- **`scheduleDates` is never populated by any view** — grepped all of `resources/`. The inline
  capacity-warning block rendered from `$scheduleWarnings[$production->id]` in
  `production-index.blade.php` is dead code. `scheduleDraftAction()` is a Filament modal; its
  `fillForm` only *reads* `scheduleDates`. Decide remove-vs-wire before carrying it into a redesign.
- **`$partialShortage` is dimensionally invalid.** It `bcadd`s `required_mass_grams` (grams) with
  `required_units` (pieces) into one number, then renders "Partially reserved — short by :short"
  (`lang/en/production_bench.php:348`). Any redesign should replace it with prose, not a number.
- **The recipe filter has no UI.** `#[Url(as: 'recipe')] $recipeFilter` is reachable from
  `resources/views/livewire/dashboard/recipes-index.blade.php:228` (`?recipe=<public_id>`), so users
  can land on a filtered list with no visible indication and no way to clear it.
- Removing the task count makes the `->with(['tasks', ...])` eager load droppable — one less query
  per page (`$production->tasks` is used only for `->count()` in this view).

Reusable precedent for an overflow menu: `resources/views/components/recipe-workbench/formula-row-actions.blade.php`
(Alpine, `x-teleport="body"`, fixed reposition, `z-[90]`) — solves the `overflow-x-auto` clipping that
`x-sticky-table-scroll` would otherwise cause. Unverified: whether teleported menus survive Livewire
morphs here, since the row checkboxes are `wire:model.live` and re-render the list on every selection.

## Implemented the redesign (owner approved the amended plan)

Six-column compact table, two-line rows led by product name. Everything from the proposal plus the
owner's corrections. All 761 tests in the production area pass; Pint clean. Still on `main`, uncommitted.

- `ProductionIndex.php`: dropped `scheduleDates`, `scheduleProduction()`, `updated()`, and the
  `fillForm` prefill; dropped the `tasks` eager load; added `updatedPaginators()` + `clearSelection()`
  on every filter hook, `clearRecipeFilter()`, `partiallyReservedIds()`, `filteredRecipeName()`.
  `scheduleWarnings()` now takes `array $datesByProduction` (required) — the Schedule modal is the
  only remaining caller and the only live capacity warning.
- New `resources/views/components/production-bench/production-row-actions.blade.php` — production-
  specific teleported overflow menu. Deliberately *not* a shared component with `formula-row-actions`
  (that one is coupled to the workbench `row` JS object).
- Removed `partially_reserved_short` from `lang/en/production_bench.php` **and** from
  `database/seeders/data/interface-translations.json` — the catalogue import test fails on any
  catalogue key that `lang/en` does not own.

Two traps hit on the way, both worth remembering:

1. **Blade compiles a leading `@production` before Alpine sees it.** An Alpine event named
   `@production-row-actions-opened.window` is parsed as Laravel's `@production` environment directive
   and the view dies with "syntax error, unexpected end of file, expecting elseif/else/endif".
   Renamed to `bench-production-row-actions-opened`. Recorded in `.ai/rules/views.md`.
2. **Removing `fillForm` also removed the mount-time guard** on the Schedule modal, so "does not open
   the scheduling calendar for another workspace production" stopped throwing. The guard still lives
   in the action body; the test was moved to `callAction` (the owner's plan sanctioned replacing those
   tests with modal coverage). The row now shows `batch_number` once allocated, else the planning
   reference — which is why "T00001 · Olive soap" no longer renders and a numbered run hides its
   planning reference.

Teleported `wire:click` does work: Livewire's `findClosest()` walks Alpine's `_x_teleportBack`.
