Verified facts worth not re-deriving:
- Stack is exact: PHP 8.5.10, Laravel 13.30.1, Livewire 4.4.3, Filament 5.7.8, Pest 4.7.8, Pint 1.30.5.
- **Laravel 13 `DB::transaction(Closure, $attempts = 1)` has NO isolation-level parameter** (vendor
  `Database/Concerns/ManagesTransactions.php:26`; only the connectors accept a static
  `isolation_level`). The plan's mandated "REPEATABLE READ transaction" cannot be expressed through

  guarded by driver, or a second connection config.

  (line 107), so imported versions must be cleared *after* the normal lifecycle, not by skipping it.

- `IngredientDataEntryService::syncSubstanceEntries()` really does default `concentration_source` to
  `supplier` and carries `source_notes`/`source_data` (must stay excluded).
- Catalogue locales are exactly 6 (de, es, fr, it, nl, pt_BR) plus `en` source; new groups need
  `config/interface-translations.php` + seeder rows.
- Test DB is `sqlite :memory:` (phpunit.xml), so the PostgreSQL concurrency file can never run in the
  default suite — skips must be reported honestly.
- No spec file exists for this feature in `docs/superpowers/specs`; only this plan.

Two conflicts with standing conventions found: Task 10 tells the executor to run `graphify update .`

## Adjudicated counter-review and updated the sharing plan

The owner pasted a counter-review of my evaluation. Verified each dispute against source, then
applied the merged corrections to `docs/superpowers/plans/2026-09-30-workspace-formula-sharing.md`.

Where the counter-review beat my findings:
- REPEATABLE READ: the plan already said "set isolation at the start of the outer transaction, before
  its first read" — the mechanism works because Laravel begins the transaction before the closure;
  my "will break" was overstated. Now the plan names the exact statement, the pgsql driver guard,
  and 40001 auto-retry (verified `Illuminate\Database\ConcurrencyErrorDetector` matches 40001).
- Task 7 already sequenced publish→clear; only wording ("after publication, inside the same
  transaction") was needed.
- AGENTS.md explicitly requires `graphify update .` after code changes and prescribes
  `php artisan test --compact` — my memory notes contradicted committed instructions; both corrected
  in MEMORY.md (the hook and the manual run coexist; CLI memory_limit is already 2048M, so the OOM
  note was likely a bad-session artifact).
- Recipe has NO soft deletes: `restore()` toggles `archived_at`; `destroy()` hard-deletes. My
  soft-delete/restore concern was wrong.
- Preview hash: bind to platform rows actually used by the share, not global catalogue state.

Where my findings survived and are now in the plan: recipient UUID lookup needs
`withoutGlobalScopes()` (OwnedByCurrentTenantScope) + "A need not be a member of B"; lineage keys
out of browser-facing serialization but kept internally; solo-owner vs entitled-Admin eligibility;
flag pinned off in phpunit.xml; explicit imported-ingredient fields (owner_type/visibility/
requires_admin_review/catalog_key); three extra substitution test cases.

New gap the counter-review caught that I missed: `accepted_product_deleted_at` — a nulled FK cannot
date B's Product deletion for the 30-day purge; stamp it via the Recipe deletion event. Added to
the plan (column + retention rules; archiving must NOT stamp it).
