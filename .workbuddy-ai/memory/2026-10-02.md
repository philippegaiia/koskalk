## CORRECTION to the "74 currency failures" claim above — it was my environment, not the repo

The earlier entry in this file, and my first report, relayed "74 failed / 4,537 passed, root-caused to
CurrencyCatalogTest" and implied the plan's green figure was stale. **That was wrong.** Codex Sol 6.1
disputed it; I reproduced the disagreement and found the cause:

- My agent shell runs with **`LANG=C`**, so `Locale::getDefault()` is empty. Symfony Intl's
  `Currencies::exists()` then returns **false for every currency** (it reads the *default-locale*
  bundle), so `CurrencyCatalog::selectableCodes()` returns `[]` and `isKnown()` is false for everything.
- `CurrencyCatalogTest`: **2 failed under `LANG=C`, 4 passed with `LANG=en_US.UTF-8`.** Same file, same
  PHP, same tree. `CurrencyCatalog` touches no database, so this was never a data/seed issue.
- Therefore the "74 failures" was a locale artifact that cascaded through currency validation, not
  pre-existing breakage on `main`. Do not repeat the claim.

Recorded as a durable rule via `record-rule` in `.ai/rules/tests.md` and in project `MEMORY.md`.
