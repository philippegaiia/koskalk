Durable facts established while reviewing (all verified against the tree or primary sources):

- `RegulatoryRegime::normalizeCode()` (`app/Models/RegulatoryRegime.php:31-45`) returns `'eu'` for
  **blank and unknown** — the fail-open bug. `RegulatoryRegime` is a Model, not an enum; `status` is a
  plain string; there is no `defaultCode()` yet.
- A deleted regime's **code string survives** on `recipe_versions` (`nullOnDelete` nulls the FK, not
  the column), so rescue-by-default is a silent market swap. Screening state must resolve at read
  time. If `normalizeCode()` becomes `?string`, `recipe_versions.regulatory_regime` must also become
  nullable with the `'eu'` default dropped, or Postgres restores `'eu'` on implicit writes.
- `SubstanceSeeder::starterRuleAttributes()` (`:145-160`) writes `watch` rules with null limits and
  `source_reference` = "Platform starter rule. Replace with official source before relying on it."
  `ruleHasSpecificComplianceData()` (`:162-170`) is the existing placeholder detector — reuse it,
  don't write a second predicate. No platform substance row can legitimately render "prohibited".
- `IfraCertificate` is `belongsTo(Ingredient)`. IFRA's own guidance: certificates are **not issued for
  raw materials** (an EO cannot have one) — only the fragrance *mixture* manufacturer issues a
  Certificate of Conformity, for a specific mixture/use level/category. All 30 flagged platform
  materials are EOs. So: aggregate fragrance load is informational only, never compared; any
  comparison uses the material's **own** use level.
- FDA true soap needs **both** (21 CFR 701.20): bulk of nonvolatile matter = alkali salts of fatty
  acids *with* detergent properties due to those, **and** labeled/sold/represented solely as soap.
  Products can be **both** cosmetic and drug — classification turns on intended use. So "saponified"
  and `blend_only` are evidence, not determinations; needs a status *set* + insufficient-information.
- 21 U.S.C. § 364e(b): the fragrance-allergen labelling **duty exists**; the *list* is left to FDA
  regulation. Say "Koskalk does not yet apply an FDA-defined list or threshold", never "US allergen
  declaration is not required today".
- `FormulaSharePresenter::settings()` filters with `array_filter` keeping only
  `is_string || is_int || is_float` — **a boolean never survives**. Carry `screening_enabled` outside
  `settings()`; don't widen the filter.
- `tests/Support/FormulaSharingFixtures.php` fragrance phase reuses `$liquid`, a plain factory
  ingredient that is not `requires_aromatic_compliance` → IFRA assertions against it read zero load
  and report "unverifiable": a false green. IFRA tests need their own fixture.
- Product families/types are DB-seeded rows (`ProductFamilySeeder.php:16,26` = `soap`, `cosmetic`),
  and factory slugs are random — slug-keyed logic needs explicit fixtures.
- `manufacturing_mode` is a plain string column (`saponify_in_formula` | `blend_only`), no enum.
